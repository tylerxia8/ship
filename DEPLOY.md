# Public Reviewer Deploy

This doc stands up a public, reviewer-facing instance of Ship on free infrastructure: **Neon** (Postgres) + **Render** (API) + **Vercel** (web). All three offer free tiers reachable via GitHub OAuth — no credit card required.

The deploy lives off of branch `shipshape/deploy` on `github.com/tylerxia8/ship`.

---

## Why this trio, not Railway

The original plan was Railway (the existing `railway.json` + `Dockerfile` were built for it). That was paused after a Cloudflare rate-limit on the deploy IP. This stack avoids Railway entirely:

| Layer | Service | Free tier | Notes |
|---|---|---|---|
| Postgres | **Neon** | 0.5 GB storage, generous compute | The Render free Postgres tier was sunsetted, so DB lives separately. |
| API | **Render** | Web service free tier (cold starts after 15 min idle) | Reuses the existing multi-stage `Dockerfile`. |
| Web | **Vercel** | Static SPA, free | Vite build via `web/vercel.json`. |

Cold starts on Render's free tier add ~30 s to the first request after idle — fine for a reviewer demo, not for production traffic.

---

## Order of operations

There's a chicken-and-egg between Render's `CORS_ORIGIN` (needs the Vercel URL) and Vercel's `VITE_API_URL` (needs the Render URL). Resolve by deploying in this order:

1. **Neon** → produces `DATABASE_URL`
2. **Render** → produces `<service>.onrender.com` URL (set `CORS_ORIGIN` to a placeholder first)
3. **Vercel** → set `VITE_API_URL` to the Render URL, produces `<project>.vercel.app`
4. **Back to Render** → update `CORS_ORIGIN` to the actual Vercel URL; redeploy

Then seed the database manually from your local shell (one-time, ~30 s).

---

## Step 1 — Neon (Postgres)

1. Sign in at https://neon.tech (GitHub OAuth).
2. Click **Create Project**. Name: `ship`. Region: pick one close to Render's (Oregon ↔ `us-west-2` is fine).
3. After creation, copy the **Connection string** (looks like `postgres://user:pass@ep-xxx.us-west-2.aws.neon.tech/ship?sslmode=require`).
4. Save it — that's your `DATABASE_URL`.

The schema and migrations will run automatically when Render starts the API (see Dockerfile `CMD`).

---

## Step 2 — Render (API)

1. Sign in at https://render.com (GitHub OAuth).
2. **New +** → **Blueprint** → connect your GitHub → pick `tylerxia8/ship` → branch `shipshape/deploy`.
3. Render reads `render.yaml`. Accept the blueprint preview. It will create one service: `ship-api`.
4. Set the two `sync: false` env vars in the service dashboard:
   - `DATABASE_URL` = the Neon connection string from Step 1
   - `CORS_ORIGIN` = `http://localhost:5173` (placeholder; we'll update after Vercel is up)
5. `SESSION_SECRET` is auto-generated by Render — no action needed.
6. Click **Deploy**. Initial build is ~5 min (Docker multi-stage).
7. Watch the logs for `>>> phase=migrate-done exit=0` then `Yjs collaboration server attached` — that means migrations ran and the server is up.
8. Once `/health` returns `{ "status": "ok" }`, note the public URL (e.g. `https://ship-api.onrender.com`).

---

## Step 3 — Vercel (web)

1. Sign in at https://vercel.com (GitHub OAuth).
2. **Add New** → **Project** → import `tylerxia8/ship` → branch `shipshape/deploy`.
3. **Root Directory**: `web/`.
4. Framework Preset: Vite (auto-detected; the `vercel.json` overrides `buildCommand` to handle the workspace `pnpm` install).
5. Add environment variable: `VITE_API_URL` = `https://ship-api.onrender.com` (the Render URL from Step 2).
6. **Deploy**. Build takes ~3 min.
7. Note the public URL (e.g. `https://ship-shipshape.vercel.app`).

---

## Step 4 — Back to Render (CORS)

1. In the Render dashboard, open the `ship-api` service.
2. **Environment** → edit `CORS_ORIGIN` → set to the Vercel URL (e.g. `https://ship-shipshape.vercel.app`).
3. Save. Render auto-redeploys (~2 min).

---

## Step 5 — Seed the database (one-time, local)

```bash
DATABASE_URL='<paste your Neon connection string>' pnpm db:seed
```

Creates the 21 users / 517 docs / 304 issues / 35 weeks that match the audit's documented seed volume. Takes ~30 s.

## Troubleshooting

- **Render build fails on the pnpm install step.** The `Dockerfile` pins `pnpm@9.15.4` and uses `--frozen-lockfile`. If `pnpm-lock.yaml` was modified between local and what was pushed, the build fails fast. Re-push the lockfile.
- **`CORS error` in the browser console.** `CORS_ORIGIN` doesn't match the Vercel URL exactly (including the `https://` scheme, no trailing slash). Update in Render env → redeploy.
- **Cold start latency.** Render's free tier sleeps after 15 min idle. First request takes ~30 s; subsequent requests are fast.
- **`relation "documents" does not exist`** after deploy. Migrations didn't run. Check the Render logs for `>>> phase=migrate-start` and any error after. The Dockerfile's `startCommand` is `migrate; then exec server` — if migrate fails, server still starts but DB queries 500.
- **Yjs WebSocket disconnects on Render free.** Render's free tier supports WebSockets, but cold-start kills the connection. Reviewers using collab features should hit the URL once to warm the dyno before testing real-time edit.
